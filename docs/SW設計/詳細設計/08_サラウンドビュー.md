## 1. 目的・適用範囲

前後左右4カメラの映像から、駐車支援用の俯瞰映像を生成する。入力は06 カメラ表示・録画が配信するフレームだけを使用し、カメラを重複して開かない。元映像の録画は同ソフトが継続する。

本機能は停車・駐車条件が確認できる場合に限定する。走行中、車速不明、駐車情報未確認では表示を許可しない。後退中も含めて速度のある駐車操作へ範囲を広げる場合は、別途要求と閾値の承認が必要。

初期設定は無効。4分割表示、歪み補正、地面への射影・合成の順に検証する。四隅や車体下の見えていない範囲を、安全な空間として補完しない。自動駐車・障害物検知・距離保証は対象外。

## 2. 要求仕様・役割

機能は実現する動作、モジュールは処理の分担、関数はモジュール内の処理単位を表す。本書のソース構成と通信名は未実装の設計案であり、採用ライブラリの標準APIと区別する。

<a id="dd-functions"></a>

### 2.1 機能一覧

| 機能ID | 機能 | 実現する動作 |
| --- | --- | --- |
| SV-F01 | 駐車条件の判定 | **開始条件・入力：** 09 OBD2車両情報取得の車速、確認済みの駐車判定入力、UI利用要求を受け取る。<br/>**確認・処理：** 値・単位・起動ID・順序・期限を確認する。0 km/hだけで駐車とせず、駐車情報の取得方法が未確定なら許可しない。<br/>**処理結果：** 利用可否と理由、許可世代を通知する。条件喪失は直ちに表示取消へ進める。 |
| SV-F02 | 校正データの確認 | **開始条件・入力：** 4カメラの実デバイス・レンズ・寸法・取付情報と保存した校正セットを受け取る。<br/>**確認・処理：** 同じ取付条件、画像方向、解像度、モデル、校正データのバージョンかを検査する。解像度変更時に行列を無条件で流用しない。<br/>**処理結果：** 全方向をまとめた有効な校正セットと補正マップを準備する。不一致なら俯瞰合成を止める。 |
| SV-F03 | 4方向の時刻合わせ | **開始条件・入力：** 06 カメラ表示・録画のFrameRefと撮影時計の対応品質を受け取る。<br/>**確認・処理：** 受信順ではなく撮影時刻の共通時間軸で選ぶ。許容時刻差・各フレーム年齢・時計誤差を確認し、待ち時間と保持件数を制限する。<br/>**処理結果：** 条件を満たす4方向を一組で渡す。揃わない古い画像を引き伸ばして使わない。 |
| SV-F04 | 歪み補正と俯瞰合成 | **開始条件・入力：** 有効フレーム集合、校正セット、有効領域マスクを受け取る。<br/>**確認・処理：** OpenCV等で歪みを補正し、地面平面へ射影して重なりを合成する。車体・非観測領域と欠落画像を別マスクで除外する。<br/>**処理結果：** 校正データのバージョン・入力時刻・有効領域付きの俯瞰映像を作る。高さのある物体の形状・距離は保証しない。 |
| SV-F05 | 表示配信と条件喪失時の停止 | **開始条件・入力：** 合成結果、最新の利用許可、入力期限、UI表示世代を受け取る。<br/>**確認・処理：** 出力直前に全条件を再確認し、期限内結果だけ通知する。非表示・負荷上昇時は合成を休止し、録画を優先する。<br/>**処理結果：** 古い結果は破棄して無効通知する。終了時はフレーム利用を解放するが、元録画を停止しない。 |

## 3. 内部構成

7モジュールに分ける。表示許可と画像処理を分離し、処理開始時だけでなく出力直前にも許可と鮮度を確認する。長い画像処理の完了を待たずに表示許可を取り消せるようにする。

### 3.4 モジュール間の処理順序

```mermaid
sequenceDiagram
 participant E as EligibilityGate
 participant F as FrameSynchronizer
 participant C as CalibrationLoader
 participant U as Undistorter
 participant B as BirdEyeProjector
 participant L as Blender
 participant Q as QualityPublisher
 E->>F: 許可世代と期限
 C-->>U: 補正マップと校正データのバージョン
 C-->>B: 地面変換と有効領域
 F->>U: 同期した4方向
 U->>B: 歪み補正画像
 B->>L: 地面画像とマスク
 L->>Q: 合成結果と入力参照
 Q->>E: 出力直前の許可確認
 E-->>Q: 現在の可否
 Q->>Q: 画像年齢と表示世代も照合
 Note over E,Q: 処理中の許可取消で旧結果を表示しない
```

条件を失った通知は画像の完成待ちをせず送る。UIも表示許可とフレーム期限を独立監視し、通信断で最後の画像が残り続けないようにする。

<a id="dd-modules"></a>

### 3.5 モジュール詳細

校正セット、入力集合、許可世代、UI表示世代を処理結果まで引き継ぐ。1枚の出力で複数の校正データのバージョンを混在させない。

<a id="dd-module-1"></a>

#### 3.5.1 EligibilityGate（利用条件の確認）

| 項目 | 内容 |
| --- | --- |
| 入力 | 車速・駐車判定・UI要求・時刻 |
| 出力 | allow、reason、eligibility_epoch、expires_at |
| 保持情報 | 入力別の最新値と起動ID・連番、許可世代 |
| 処理 | 全条件のANDで許可。連続停車確認とヒステリシスは実機確定。条件喪失を遅延させない |
| 関数 | evaluate_eligibility |
| 異常時 | 不明・期限切れ・走行を拒否。GPS推定速度を無断で代替しない |

<a id="dd-module-2"></a>

#### 3.5.2 FrameSynchronizer（4方向の時刻合わせ）

| 項目 | 内容 |
| --- | --- |
| 入力 | 期限付きFrameRef、時刻対応誤差 |
| 出力 | FrameSetまたは揃わない理由 |
| 保持情報 | 方向別の有限キュー、最新ストリームID、共通時刻 |
| 処理 | 誤差込みの最大時刻差を満たす最新組を選択。余った参照を必ず解放 |
| 関数 | select_frame_set |
| 異常時 | 時刻不明・欠落で正常な4方向を作らない。再接続時は旧組を破棄 |

<a id="dd-module-3"></a>

#### 3.5.3 CalibrationLoader（校正の読込・検査）

| 項目 | 内容 |
| --- | --- |
| 入力 | 校正ファイルと現在カメラ情報 |
| 出力 | 不変CalibrationSet |
| 保持情報 | 校正データのバージョン、ハッシュ、camera_id、解像度、レンズモデル |
| 処理 | 4方向の整合、行列の次元・有限値・座標系・取付を検査し、一組で適用 |
| 関数 | load_calibration |
| 異常時 | 部分成功で合成しない。変更時は処理世代を進める |

<a id="dd-module-4"></a>

#### 3.5.4 Undistorter（レンズ歪み補正）

| 項目 | 内容 |
| --- | --- |
| 入力 | 画像、モデル別マップ |
| 出力 | 補正画像と画素有効マスク |
| 保持情報 | 校正と画像寸法ごとの再利用マップ |
| 処理 | 魚眼・通常モデルを区別し、採用モデルに合うOpenCV関数でremap |
| 関数 | build_remap、undistort_frame |
| 異常時 | モデル不一致・領域外を無効化。黒画素を路面情報として扱わない |

<a id="dd-module-5"></a>

#### 3.5.5 BirdEyeProjector（地面座標への変換）

| 項目 | 内容 |
| --- | --- |
| 入力 | 補正画像、地面変換、出力座標設定 |
| 出力 | 方向別地面画像と有効範囲 |
| 保持情報 | 校正済み変換行列、m/pixel、原点 |
| 処理 | 補正後の画像座標から同じ地面平面へ変換。変換を二重適用しない |
| 関数 | project_ground |
| 異常時 | 地平線近傍・射影不能・非観測領域を除外 |

<a id="dd-module-6"></a>

#### 3.5.6 Blender（重なり領域の合成）

| 項目 | 内容 |
| --- | --- |
| 入力 | 方向別地面画像とマスク |
| 出力 | 合成画像、観測マスク、品質指標 |
| 保持情報 | 固定重みマップと車体マスク |
| 処理 | 有効な重みだけ正規化。未観測画素を過去映像や生成画像で補完しない |
| 関数 | blend_views |
| 異常時 | 入力不足は縮退・無効状態。通常4方向合成として返さない |

<a id="dd-module-7"></a>

#### 3.5.7 QualityPublisher（映像・利用可否の通知）

| 項目 | 内容 |
| --- | --- |
| 入力 | 合成結果、許可状態、UI購読 |
| 出力 | SurroundFrameRefとsurround.status |
| 保持情報 | 出力連番、購読ID、display_generation、有界バッファ |
| 処理 | 最も古い入力の期限と許可期限を出力へ引継ぐ。制御取消と映像を同一世代で扱う |
| 関数 | publish_result、invalidate_output、stop_surround |
| 異常時 | 遅延・通信断で最終画面を正常に固定しない。未解放領域を再利用しない |

### 3.7 関数のフローチャート

画像処理関数は入力参照とバージョンを保持して結果を返す。終了・例外経路でも取得済みフレームを解放する。

<a id="dd-fn-evaluate-eligibility"></a>

#### 3.7.1 evaluate_eligibility（停車・駐車条件を確認する）

| 項目 | 内容 |
| --- | --- |
| 担当 | EligibilityGate |
| 入力 | 入力状態と利用要求 |
| 戻り値・結果 | 許可または拒否理由 |

```mermaid
flowchart TB
 A(["判定"]) --> B{"全入力の出所・期限・値が有効？"}
 B -->|"いいえ"| X(["許可取消"])
```

<a id="dd-image-api"></a>

### 4.3 校正・画像処理ライブラリ

魚眼モデルの校正とマップ生成にはOpenCVのfisheye系、通常モデルには対応する通常系を用いる。レンズを魚眼と仮定して同じ係数を使い回さない。[OpenCV魚眼モデル](https://docs.opencv.org/4.13.0/db/d58/group__calib3d__fisheye.html)

remapとwarpPerspective等の既存変換を用い、出力座標から入力画像への対応・補間・境界処理を明確にする。使用する行列が補正前画像用か補正後画像用かを校正データに記録する。[OpenCV幾何変換](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)

自動パノラマ合成だけで車体周辺の地面座標が決まるとは考えない。既知の地面基準点と固定したカメラ取付を用いて校正し、実装では採用するOpenCVのバージョンを固定する。

## 5. データ・設定設計



<a id="dd-calibration"></a>

### 5.1 校正セットと座標系

| 項目 | 内容 |
| --- | --- |
| calibration_version / checksum | 4方向を一組で管理するバージョンと内容識別 |
| camera_id / device_identity / lens_model | 実カメラ・レンズとの対応。front/rear/left/right |
| width / height / crop / orientation | 解像度・切出し・画像回転・左右反転の設定 |
| K / distortion / rectified_K | 内部行列、モデル固有の歪み係数、補正後の内部行列 |
| ground_transform / transform_direction | 補正画像と地面座標の対応・変換方向 |
| valid_mask / vehicle_mask | 観測可能範囲と車体占有領域。車体下を現在映像で埋めない |
| mounting_profile / calibration_conditions | 取付位置・向き・車高・校正時の条件 |
| acceptance_record | 基準点誤差・境界ずれ・対象範囲と試験結果 |
座標は車体中心等の固定基準を原点とし、車体前方+x、左+y、上+zを採用する設計案。俯瞰画像は前方を上、左を左とし、pixel/mの対応を明記する。原点の実位置、車体寸法、表示範囲は測定して確定する。見た目が合うだけで変換方向を判断しない。

<a id="dd-freshness"></a>

### 5.2 同期判定と画像寿命

```text
frame_interval_i = [capture_time_i - uncertainty_i,
                    capture_time_i + uncertainty_i]

worst_case_skew =
    max(capture_time_i + uncertainty_i)
  - min(capture_time_i - uncertainty_i)

output_deadline =
    min(each_input_deadline, eligibility_deadline)
```
同じPi 5上の比較可能な時間軸へ対応できた時刻だけを用いる。前後サブコンの単調時計を左右CSIの時計と直接比較しない。時計誤差不明なら同期不可とする。

操作要求の期限は受付時に検査する。受理済みの映像利用はsubscription_idと利用者接続で管理し、操作要求の期限をそのまま全フレームの表示終了時刻にはしない。利用解除・UI切断・表示世代変更で配信を停止する。利用継続の期限を別途設ける場合は、独立した更新手順を定め、その期限もoutput_deadlineへ含める。

時刻差が許容値以内でも、4枚とも古ければ無効。処理終了時にも入力年齢と出力期限を再確認する。期限を合成完了時刻から付け直さず、途中で待った時間も画像寿命に含める。有限キューを超える候補は解放し、同じ過去画像を新しい連番で再配信しない。

<a id="dd-runtime"></a>

### 6.2 校正変更・負荷増大時の処理

校正・解像度・取付設定の変更では許可を取り消し、処理中結果を破棄して新しい校正セットを一括適用する。古い校正バージョンのフレームと新しい校正バージョンの変換を混ぜない。

負荷が高い場合は承認済みの低負荷プロファイルへ切り替えるか合成を休止する。06 カメラ表示・録画の録画設定を直接変更しない。出力解像度だけを変更する場合も、地面スケールと出力マスクを一緒に更新する。

路面平面の仮定から外れる坂、縁石、人、車等は伸びや二重像が生じ得る。継ぎ目を滑らかにしたことを距離精度の改善と扱わない。

<a id="dd-7"></a>

## 7. 異常処理

| 異常 | 動作 |
| --- | --- |
| 車速・駐車情報不明 | 許可取消と無効通知。停止と推測しない |
| 時計対応不明・遅延超過 | 同期組を作らず、旧フレームを解放 |
| 校正・取付・解像度不一致 | 合成禁止。自動スケール補正でごまかさない |
| カメラ1台断 | 通常の4方向表示を停止。欠落領域を明示 |
| 画像処理例外・メモリ不足 | 保有フレームを解放し、負荷を下げて有限再試行 |
| UI解放応答なし | 当該配信を停止。領域を安全確認前に再利用しない |
| 録画負荷・高温 | 合成休止を優先し、状態をUIへ通知 |

<a id="dd-8"></a>

## 8. 起動・終了・運用設計

起動時は設定と校正だけを準備し、駐車条件と利用要求が揃うまで映像利用を開始しない。入力側の06 カメラ表示・録画は独立して動く。

終了時は先に出力を無効化し、未完了結果を破棄し、貸出・取得済みフレームを解放する。UIを閉じた場合は合成用の利用だけを解除する。再開時は最新車両値・最新フレームから始める。

校正は平坦な試験場所で車体を確実に停止し、位置と寸法が分かる基準マーカーを使って行う。運転者の直接確認に代わる装置として運用しない。
