## 1. 目的・適用範囲

Raspberry Pi 3Bのサブコントローラ2で前方CSIカメラと左右ウィンカーの保護済みGPIO信号を取得し、EthernetでPi 5へ送る。
前方カメラ、左右信号監視、点滅継続の推定、サブコン2通信を本ソフトにまとめる。GPIOとCSIカメラは実機依存のため、代替ドライバによるdry-runを含む内部実装として提供する。

[06 カメラ表示・録画](06_カメラ表示録画.md)が前方映像を受信し、[01 カーナビUI](01_カーナビUI.md)が状態に応じた画面表示を判断する。本ソフトはウィンカー出力、左右カメラの取得、画面の強制切替を行わない。左右カメラはPi 5側で取得する。
[15 サブコントローラ1後方系](15_サブコン1後方系.md)とは設計方針を合わせるが、GPIOの割当や入力状態を共用しない。

## 2. 要求仕様・役割



<a id="dd-functions"></a>

### 2.1 機能一覧

| ID | 機能 | 実現する動作 |
| --- | --- | --- |
| SUB2-01 | 起動・個別経路の監視 | 開始条件・入力: 設定と起動要求。確認・処理: 共通設定、左右GPIO、カメラを分けて検証。処理結果: 正常な経路を開始し、使えない経路を理由付きで通知する。 |
| SUB2-02 | 左右ランプ状態の取得 | 開始条件・入力: 左右の保護済みGPIO。確認・処理: 片側ずつ初期安定待ちとノイズ除去を行い、極性をON/OFFへ変換。処理結果: 左右別の値、観測時刻、品質を生成する。 |
| SUB2-03 | 点滅操作継続の推定 | 開始条件・入力: 確定したランプ状態と変化時刻。確認・処理: ONまたは直近の消灯からの保持窓で活動を推定し、長時間ONや読取停止を別判定。処理結果: 左右のactivityと根拠・期限を生成する。 |
| SUB2-04 | 両側活動の整理 | 開始条件・入力: 左右activityと各品質。確認・処理: 両方の情報が有効かを確認して組合せを評価。処理結果: both_activityを通知する。ハザードスイッチ操作を確定したとは扱わない。 |
| SUB2-05 | 前方映像の送信 | 開始条件・入力: CSIカメラと映像設定。確認・処理: 取得・符号化・撮影時刻対応を行い、容量を制限して転送。処理結果: camera_id=frontを06 カメラ表示・録画へ送る。 |
| SUB2-06 | 通知・再接続・終了 | 開始条件・入力: 状態変化、定期時刻、通信障害、停止要求。確認・処理: 最新状態を期限付きで通知し、復旧時に古い映像・推定履歴を破棄。処理結果: 新規観測から再判定し、終了時は各資源を解放する。 |

<a id="dd-function-module-map"></a>

### 2.2 機能・モジュール・関数の対応

| 機能 | モジュール | 関数案 |
| --- | --- | --- |
| SUB2-01・06 | Supervisor | start / check_health / stop |
| SUB2-02 | TurnSignalMonitor | read_inputs / update_channel / invalidate_channel |
| SUB2-03・04 | BlinkActivityEstimator | update_activity / evaluate_both / reset |
| SUB2-05 | FrontCameraService | start_stream / capture_and_send / reset_stream |
| SUB2-06 | Sub2Api | publish_state / handle_request / reconnect |

ランプの生状態を取得する機能と、消灯区間でも操作継続中とみなす推定機能は別である。推定値を生のGPIO値として上書きしない。

### 3.2 機能別処理フローチャート



<a id="dd-feature-1"></a>

#### 3.2.1 起動と独立監視（SUB2-01）

```mermaid
flowchart TB
 A["Supervisor: 共通設定を検証"] --> B{"有効？"}
 B -->|"いいえ"| X["FAULT"]
 B -->|"はい"| C["boot_id生成 / 状態通信開始"]
 C --> D["左右GPIOとカメラを個別初期化"]
 D --> E["BlinkActivityEstimator: 履歴なし"]
 E --> F["各経路の状態を通知"]
 F --> G["正常な経路を継続"]
```

<a id="dd-feature-2"></a>

#### 3.2.2 左右ランプの観測（SUB2-02）

```mermaid
flowchart TB
 A["TurnSignalMonitor: 左を読む"] --> B{"左読取成功？"}
 B -->|"はい"| C["左候補・観測を更新"]
 B -->|"いいえ"| D["左だけUNKNOWN"]
 C --> E["右を読む"]
 D --> E
 E --> F{"右読取成功？"}
 F -->|"はい"| G["右候補・観測を更新"]
 F -->|"いいえ"| H["右だけUNKNOWN"]
 G --> I["左右別の値と品質を配信"]
 H --> I
```

一方の読取例外で他方の読取を省略しない。左右は同時刻の完全な一括取得ではないため、各観測時刻を持つ。

<a id="dd-feature-3"></a>

#### 3.2.3 活動の保持と解除（SUB2-03）

```mermaid
flowchart TB
 A["BlinkActivityEstimator: 片側の観測"] --> B{"観測と推定設定が有効？"}
 B -->|"いいえ"| U["activity UNKNOWN"]
 B -->|"はい"| C{"安定ランプON？"}
 C -->|"はい"| D{"連続ONが上限以内？"}
 D -->|"はい"| E["activity ACTIVE / 根拠LAMP_ON"]
 D -->|"いいえ"| U
 C -->|"いいえ"| F{"有効な消灯履歴の保持窓内？"}
 F -->|"はい"| G["activity ACTIVE / 根拠OFF_HOLD"]
 F -->|"いいえ"| H["activity INACTIVE"]
 E --> I["根拠と期限を付ける"]
 G --> I
 H --> I
 U --> I
```

OFF_HOLDは新しいOFF観測のたび延長しない。最後の確定ON→OFF変化時刻から固定時間だけ保持する。

<a id="dd-feature-4"></a>

#### 3.2.4 両側活動の判定（SUB2-04）

```mermaid
flowchart TB
 A["左右の活動と有効期限"] --> B{"両側とも有効？"}
 B -->|"いいえ"| U["both_activity UNKNOWN"]
 B -->|"はい"| C{"両側ともACTIVE？"}
 C -->|"はい"| Y["both_activity ACTIVE"]
 C -->|"いいえ"| N["both_activity INACTIVE"]
 Y --> D["ハザード状態は未取得のまま"]
 N --> D
 U --> D
```

両側活動は推定保持窓の重なりでも成立し得る。左右が交互に操作された場合を含め、ハザードスイッチONと同一視しない。

<a id="dd-feature-5"></a>

#### 3.2.5 前方映像と状態の並行送信（SUB2-05・06）

```mermaid
flowchart TB
 A["FrontCameraService: 取得・符号化"] --> B["容量制限付き映像送信"]
 B --> C{"送信待ち上限超過？"}
 C -->|"はい"| D["映像欠落を記録 / 再同期"]
 C -->|"いいえ"| A
 E["TurnSignalMonitor: 新規観測"] --> F["BlinkActivityEstimator: 更新"]
 F --> G["Sub2Api: 状態通知"]

```

映像・状態で送信待ち領域と実行待ちを分ける。実際の並行実行方式はPi 3Bの負荷試験で確定する。

#### 3.2.6 再接続時の履歴破棄（SUB2-06）

### 3.4 モジュール間の処理順序

```mermaid
sequenceDiagram
 participant G as TurnSignalMonitor
 participant E as BlinkActivityEstimator
 participant A as Sub2Api
 participant U as 01 カーナビUI
 participant C as FrontCameraService
 participant R as 06 カメラ表示・録画
 par 左右信号
  G->>E: 左ON確定 / 右OFF確定
  E->>A: 左ACTIVE / 右INACTIVE
  G->>A: 生状態と品質
  A-->>U: 観測・推定・根拠・期限
  G->>E: 左OFF確定
  E->>A: 左ACTIVE / OFF_HOLD
  A-->>U: ランプOFFと活動保持を別通知
  E->>E: 消灯から保持期限に到達
  E->>A: 左INACTIVE
```

### 3.5 モジュール詳細



<a id="dd-module-1"></a>

#### 3.5.1 Supervisor（開始・終了・部分故障管理）

| 項目 | 設計内容 |
| --- | --- |
| 入力 | 設定、停止要求、左右GPIO・映像・通信の処理進行情報。 |
| 出力 | 経路別の開始・停止、再試行、サービス状態。 |
| 保持情報 | boot_id、設定世代、経路状態、再試行時刻、停止期限。 |
| 処理 | 共通条件が有効なら経路別に開始。片側の異常で全体を正常とはしないが、他側と映像は継続可能。 |
| 関数 | start(config)、check_health(now)、stop(deadline)。 |
| 異常時 | 停止したカメラ処理を待ってGPIO監視を止めない。故障側の候補と推定履歴だけを破棄する。 |

<a id="dd-module-2"></a>

#### 3.5.2 TurnSignalMonitor（左右別の安定したランプ状態）

| 項目 | 設計内容 |
| --- | --- |
| 入力 | left_gpio、right_gpio、各極性、安定判定時間、読取周期。 |
| 出力 | left_lamp/right_lamp=ON/OFF/UNKNOWN、各validity・reason・観測番号。 |
| 保持情報 | 左右それぞれraw_level、candidate、candidate_since、stable_level、last_read、last_rise、last_fall。 |
| 処理 | 初回はUNKNOWN。候補が継続した側だけ安定値を変更し、その時刻を変化時刻として記録。 |
| 関数 | read_inputs(now)、update_channel(side, raw, now)、invalidate_channel(side, reason)。 |
| 異常時 | 監視空白・読取失敗の側をUNKNOWNにし、復旧時は安定待ち。LOWから断線を確定しない。 |

<a id="dd-module-3"></a>

#### 3.5.3 BlinkActivityEstimator（点滅継続の推定）

| 項目 | 設計内容 |
| --- | --- |
| 入力 | 左右の確定ランプ状態、各変化時刻・品質、now、推定設定。 |
| 出力 | left_activity/right_activity、both_activity、inferred=true、根拠、残り有効時間。 |
| 保持情報 | 左右別ON開始、最後の確定消灯、hold_until、入力の観測番号、推定有効性。 |
| 処理 | 有効なONなら活動あり。OFFへ変化後は固定の保持窓だけ活動あり。期限後は活動なし。初期OFFで過去ONがなければ活動なし。 |
| 関数 | update_activity(side, sample, now)、evaluate_both(now)、reset(side_or_all)。 |
| 異常時 | 観測期限切れ・監視空白・連続ON上限超過はUNKNOWN。推定パラメータ未確定なら推定だけ無効にして生値は送る。 |
| 境界 | OFF保持中にONへ戻れば新しいON区間。OFFの再読取でhold_untilを延長しない。 |

<a id="dd-module-4"></a>

#### 3.5.4 FrontCameraService（前方映像取得・送信）

| 項目 | 設計内容 |
| --- | --- |
| 入力 | CSIカメラ、映像設定、Pi 5接続先。 |
| 出力 | front映像、撮影時刻・品質、カメラ状態・欠落数。 |
| 保持情報 | デバイス、符号化処理、stream_session_id、sequence、上限付き送信待ち領域。 |
| 処理 | 映像は06 カメラ表示・録画へ直接送る。左右の車体信号処理と別の実行待ち・送信待ちを用いる。 |
| 関数 | start_stream(profile)、capture_and_send()、reset_stream(reason)。 |
| 異常時 | 欠落後は有効な復号開始点を待つ。撮影時刻不明を受信時刻で置換しない。 |

<a id="dd-module-5"></a>

#### 3.5.5 Sub2Api（状態通信）

| 項目 | 設計内容 |
| --- | --- |
| 入力 | 左右の生状態と活動推定、経路状態、相手からの状態参照要求。 |
| 出力 | 観測ごとの時刻・品質を保った状態通知、拒否理由、再接続結果。 |
| 保持情報 | peer_id、boot_id、通知sequence、最新状態、接続世代、再試行時刻。 |
| 処理 | 左右と推定の値を別項目で配信。サービス生存通知で車体観測の期限を更新しない。 |
| 関数 | publish_state(snapshot, now)、handle_request(request)、reconnect(now)。 |
| 異常時 | 片側の異常を理由付きで送信。通信断で両側OFFを生成しない。 |

<a id="dd-freshness"></a>

### 4.2 鮮度と受信側の判断

通知は[共通仕様](00_共通仕様.md)に合わせる。左右ごとに観測時刻・経過時間・validityを付け、外側のサービス生存時刻だけで左右入力を有効にしない。
推定には根拠となるsample_sequenceとinferred=trueを付ける。OFF_HOLDでは元の消灯からの残り時間と入力観測の残り寿命の短い方まで有効とする。

01 カーナビUIは期限切れ・UNKNOWNを表示判断に使わず、後方表示などの優先順位と合わせて採否を決める。両側活動だけで左右カメラを交互に強制表示しない。
boot_id、source=sub2、schema_versionを確認し、front映像と後方サブコンのrear映像を混同しない。

異なるPiの単調時計は直接比較しない。観測から送信までの経過時間、受信後経過、検証済み通信遅延上限を含めて鮮度判定する。撮影時刻の品質不明は06 カメラ表示・録画へ明示し、同期済みとして俯瞰合成へ流さない。

<a id="dd-activity-state"></a>

### 6.1 活動推定の状態

```mermaid
flowchart LR

 U -->|"初期安定OFF"| I["INACTIVE"]
```

<a id="dd-state-table"></a>

### 6.2 組合せと部分異常

| 左活動 | 右活動 | both_activity | 扱い |
| --- | --- | --- | --- |
| ACTIVE | INACTIVE | INACTIVE | 左活動のみ |
| INACTIVE | ACTIVE | INACTIVE | 右活動のみ |

<a id="dd-7"></a>

## 7. 異常処理

| 異常 | 動作 | 禁止する扱い |
| --- | --- | --- |
| 片側読取失敗 | その側のlampとactivityをUNKNOWN、履歴破棄 | 他側も一律OFFにする |
| 点滅間の消灯 | 生状態OFF、期限内のみOFF_HOLD | 消灯を必ず断線と判定 |
| 連続ONが上限超過 | lamp=ONの観測は残し、activityはUNKNOWN/異常理由 | 正常な点滅継続と断定 |
| 短すぎる点滅・ノイズ | 生値、安定判定結果、欠落した変化を試験ログで照合 | ソフトだけで電気ノイズを完全除去できるとする |
| 監視ループ停止 | 入力期限超過、候補・推定を破棄 | 古い活動を最新状態で再通知 |
| カメラ異常 | 映像FAULT、信号は継続 | 録画障害をウィンカーOFFに変換 |
| 通信断 | 受信側のTTLで無効化し再接続時履歴破棄 | 古い点滅履歴を再送して画面を切替 |
| GPIO LOW | 極性に従って扱い、診断能力の限界を明示 | 回路根拠なく配線正常または断線を断定 |
| 時刻対応不明 | clock_quality=UNKNOWN | 受信時刻を撮影時刻とする |

<a id="dd-8"></a>

## 8. 起動・終了・運用設計

専用サービスとして設定・接続相手を確認した後、左右入力と前方映像を独立に開始する。GPIOは読取専用。起動直後の左右lamp/activityはUNKNOWNで、初期安定待ちを省略しない。
状態通信が再接続した場合は両側の候補と点滅推定履歴を初期化する。片側だけのGPIO復旧では正常側の履歴を消さない。

映像処理と信号処理の実行待ちを分け、Supervisorがどちらの処理も監視できるようにする。解像度・fps・符号化方式はPi 3Bの実測で決める。CPU、温度、メモリ、フレーム欠落、信号通知遅延を記録する。
通常ログには状態変化・理由・時刻・観測番号を残し、全映像や秘密情報を含めない。

停止時は新規受付と取得を止め、推定を無効化して可能なら停止状態を送る。その後、カメラ・GPIO・通信を解放する。給電停止のタイミングはサブコンのHW電源設計と整合させ、Pi 5が止まったことだけでPi 3Bが安全に停止済みとは判断しない。

## 用語の注釈

| 用語 | 意味 |
| --- | --- |
| 生値 / 安定値 | GPIOの読取値 / 一定時間の確認後に採用した値。 |
| 活動推定 | ランプが消えている点滅の合間も、操作が続いている候補として一定時間扱うこと。 |
| 保持窓 | 最後の確定消灯から活動ありを維持する有限の期間。 |
| ハイフラ | 通常より速い点滅。入力回路と安定判定が追従するか確認する対象。 |
| 部分稼働 | 一部の経路が故障しても、独立した正常経路を動かし続けること。 |
