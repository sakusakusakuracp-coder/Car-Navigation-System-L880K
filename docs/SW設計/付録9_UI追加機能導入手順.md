## 1. 前提

UIは既存のPySide6/QML起動方法を使用する。追加機能はサービスを勝手に起動せず、未接続時には状態と操作失敗を表示する。録画・送信・冷却を使用する場合は、それぞれ[付録8](付録8_カメラ表示録画導入手順.md)、[付録7](付録7_GoogleDriveアップロード導入手順.md)、[付録6](付録6_周辺サービス実装・実機導入手順.md)に従って先に起動する。

UI、カメラ、送信、冷却のUnixソケットは同じ運用ユーザーで扱う。Windowsでは画面とHTTP音楽連携を試験できるが、Linux専用ソケットや機器の動作確認とは区別する。

## 2. 接続先

`~/.config/l880k-car-navigation/ui.json`の既存項目を残し、必要な接続先だけ追加する。以下は省略時の値または配置例。

| 項目 | 値・用途 |
| --- | --- |
| `mopidy_url` | `http://127.0.0.1:6680/mopidy/rpc` |
| `audio_sink_name` | 任意。PulseAudio互換サーバー上のUSB DAC出力名。指定がない場合は監視対象未指定と表示 |
| `camera_config_path` | `~/.config/l880k-car-navigation/camera.json`相当の絶対パス。UIと録画サービスで同じ台帳・保存先を使う |
| `preferences_path` | `~/.config/l880k-car-navigation/preferences.json`相当の絶対パス。通常は省略 |
| `camera_socket_path` | `$XDG_RUNTIME_DIR/l880k-camera.sock` |
| `drive_upload_socket_path` | `$XDG_RUNTIME_DIR/l880k-drive-upload.sock` |
| `fan_socket_path` | `$XDG_RUNTIME_DIR/l880k-fan.sock` |

JSON内では環境変数の展開を行わないため、ソケットや利用者設定のパスを指定するときは実際の絶対パスを使う。省略した場合は実行ユーザーの標準パスを使用する。UI設定ファイルにGoogleの認証トークン等を入れない。

## 3. 音楽

Mopidy本体、利用するライブラリ拡張、音声出力先を運用環境へ導入し、HTTP機能を有効にする。設定・導入は[Mopidy公式インストール手順](https://docs.mopidy.com/stable/installation/)と[HTTP設定](https://docs.mopidy.com/stable/ext/http/)を参照する。外部ネットワークへHTTP操作ポートを公開しない。

UIを起動する前に、Mopidyが実行中の環境で次を確認する。

```bash
curl -sS http://127.0.0.1:6680/mopidy/rpc \
  -H 'Content-Type: application/json' \
  --data '{"jsonrpc":"2.0","id":1,"method":"core.playback.get_state"}'
```

エラーではなく`result`が返ることを確認する。ライブラリの曲をキューへ追加し、キュー内の曲を選ぶと再生する。音量とシークはスライダーを離したときに送信する。通信失敗時に操作を自動再送せず、次の状態取得で実状態を確認する。

接続タイムアウトは各HTTP要求2秒、状態取得開始間隔は1秒、同じ照会を並列実行しない。最後の取得成功から5秒で更新停止扱いとする。HTTP・DNS・OS入出力の総時間を2秒に保証するものではない。曲名・時間・キュー・音量はMopidyの応答を使う。音量が未提供なら操作を無効にする。

ライブラリと検索結果は50件ずつ表示し、501件以降も切り捨てない。Mopidyからは一覧全体を取得してページ分割するため、サーバー側ページングではない。HTTP応答の上限は2MBで、超過時は失敗を表示する。検索は`core.library.search`の`any`条件で行い、利用可能な音源・検索範囲はバックエンドに従う。

「プレイリスト」で保存済み一覧を開く。作成、名前変更、曲順変更、曲の除外、現在の再生キューの末尾追加、保存、削除に対応する。曲ファイルそのものは削除しない。「キューへ」は保存済みの内容を再生キューへ追加し、自動再生しない。名前や曲順の編集は保存までサーバーへ送らず、「再取得」または別リストの選択で未保存の編集を破棄する。空リストの作成は即時保存。削除は確認ダイアログ後に実行する。編集と作成・保存・削除には停車確認が必要。

書込対応のプレイリストバックエンドが必要で、拒否・未対応の応答は成功にしない。保存・削除直前に元データを再取得して外部変更を検出する。ただしMopidy APIは条件付き更新ではないため、確認から保存までの他アプリによる変更を完全には排除できない。運用中は編集元をこのUIに限定する。APIは[Mopidy Core API](https://docs.mopidy.com/stable/reference/core/)に従う。

USB DAC監視はLinuxのPulseAudio、またはPipeWireのPulseAudio互換サーバーに対する読取専用の照会。UIと同じユーザーで次を実行し、`properties.device.bus`が`usb`の出力の`name`を`ui.json`の`audio_sink_name`へ指定する。

```bash
pactl --format=json list sinks
```

1秒間隔で照会を開始し、同じ照会は重複させず、コマンドの待ち時間は最大3秒、取得成功後5秒で状態を失効させる。未接続時は警告履歴にも記録する。照会失敗時は「確認できません」と表示し、接続・切断を断定しない。Windowsは監視対象外。`pactl`が利用できること、指定名が再起動後も安定していることを実機で確認する。

「USB音声出力: 接続」は出力デバイスの存在だけを意味する。Mopidyの音声が実際にそのDACへ流れているかは保証せず、経路・ミュート・既定出力は変更しない。抜去時のHDMI等への自動迂回防止は未実装で、ホスト音声設定で別途確認する。

この実装はUI内の通信処理であり、`audio_integration_service.py`という独立常駐プログラムはまだ作成していない。ナビ案内中の音量低減、DAC抜差し時の出力制御、音源スキャンは未実装。UI終了でMopidyを停止しない。OsmAndの起動中を発話中とみなして音量を下げない。

### 3.1 YouTube Music・Spotifyの公式Web画面

音楽画面の音源を「保存済み音楽」「YouTube Music」「Spotify」で切り替える。保存済み音楽は従来のMopidy操作、公式サービスはChromiumで公式サイトを開く方式とする。YouTube PremiumにはYouTube Music Premiumの特典が含まれるため、契約済みのGoogleアカウントを公式画面で使用する。[YouTube公式ヘルプ](https://support.google.com/youtube/answer/6308116?hl=ja)

| 音源 | 接続先 | 操作・契約条件 |
| --- | --- | --- |
| YouTube Music | [公式Webプレーヤー](https://music.youtube.com/) | 公式画面でログイン・検索・選曲・再生・音量変更。契約状態はサイト側で確認する |
| Spotify | [公式Webプレーヤー](https://open.spotify.com/) | Spotify側のアカウントと利用条件に従う。YouTube Premium契約をSpotify Premiumとして扱わない |

非公式の音源取得拡張、音声抽出、広告除去、DRM回避は使用しない。自作UIはWebページの内容・パスワード・再生状態を読み取らず、「公式画面を表示」は再生成功やログイン成功を意味しない。Spotifyの保護コンテンツ再生には対応ブラウザの設定が必要で、Pi 5/ARM64上のChromiumでの実再生は未確認。[Spotify公式Web Playerヘルプ](https://support.spotify.com/jp/article/web-player-help/)

#### 導入と起動

1. Debian 13またはPi 5のLinux上にChromiumを導入する。例: `sudo apt install chromium`。ブラウザをrootで起動しない。
2. 既存のSway用スクリプトからUIを起動する。`WAYLAND_DISPLAY`、`SWAYSOCK`をUIとブラウザで共有し、UIはSway内の通常ウィンドウとする。WindowsやGNOMEだけのセッションでは公式画面の配置を行わず、必要環境を表示する。
3. 有効期限内のOBD2車速0を確認した状態で「音楽」→「YouTube Music」または「Spotify」を選ぶ。音源ボタンを押すと公式画面を自動起動する。OBD2未接続・車速未取得・車速値失効時は、画面に警告を表示したうえで停車確認なしの代替モードとして開ける。自動試験の停車通知注入と実運用を区別し、この代替モードは実車の安全インターロックではない。
4. 公式画面で本人がログインし、再生する。自作UIへ認証情報を入力しない。Spotifyも同様だが、未契約の有料機能を利用可能とは表示しない。
5. 下部のホーム・ナビ等で別画面へ移動すると、公式ブラウザを専用の非表示ワークスペースへ移動する。プロセスとページ状態を維持し、音声を継続できるかは公式サイトの動作と契約に従う。音楽画面に戻り停車を確認すると同じウィンドウを再配置する。「終了」、別音源への切替、UI正常終了では専用ブラウザを閉じる。

Sway上の外部ウィンドウを音楽画面の中央へ配置する方式であり、QMLへのWebページ埋込みではない。上部の音源切替と下部の画面切替を残し、Mopidy用の曲名・再生・音量・プレイリスト操作を公式Web画面には重ねない。QMLがウィンドウ内の座標を送り、Sway上のUIの位置を加算して配置する。800×480と1280×720の操作部は自動描画試験で確認するが、実ブラウザの最小サイズ・表示倍率・マルチモニター・ポップアップの実配置は別途検証する。

#### 状態・終了・認証情報

- 公式URLは上記2つに固定。専用プロファイルは`~/.config/l880k-car-navigation/web-music/youtube_music`、`spotify`。ログイン状態はChromiumが保存し、UI設定バックアップとGitの対象に含めない。ログアウトは公式サイトから行う。UI側でCookieやトークンを採取しない。
- ブラウザは利用者権限と通常のサンドボックスで起動する。専用プロファイルを手動のChromiumと同時利用しない。管理操作は所有するプロセスのPIDとSwayコンテナIDで限定し、同名の個人ブラウザやWaydroidを操作しない。
- 配置処理は単一の実行枠で直列化し、500ms周期で確認する。Swayコマンドのタイムアウトは各2秒、起動後20秒を超えて対応ウィンドウが見つからなければ失敗とし、ブラウザを閉じる。停止と画面離脱で古い配置要求を無効にする。失敗後の再起動は「開く」の明示操作だけで行う。
- 有効な車速が走行中を示す場合は公式画面を非表示にする。車速未取得・未接続・車速値失効では、警告を表示した代替モードとして公式画面を表示できる。停車確認期限だけが切れた場合は、OBD2車速が有効なら通常どおり非表示にする。画面は専用の非表示ワークスペースへ移動し、音声は停止せずサイト側に任せる。退避処理に失敗した場合は専用ブラウザを終了する。画面非表示は非同期であり、即時の安全インターロックではない。実車では通知遅延・新規ポップアップ・配置前の短い表示を含めて検証する。
- Mopidyで再生中と観測できている場合は、一時停止と読戻しの後で公式ブラウザを開く。停止に失敗したら開かない。Mopidy未接続時はブラウザ単独で開けるが、未観測のMopidy・他アプリとの混音までは保証しない。保存済み音楽への切替では公式ブラウザの終了を待ってMopidy操作を再開する。
- ブラウザの音声出力先と音量はホスト音声設定・公式画面を使用する。ナビ案内時の自動音量低減や公式サイトの曲情報の自作UI同期は未実装。自動再生、オフライン保存、バックグラウンド再生を独自実装しない。
- UIの強制終了・電源断では終了処理が走らない場合がある。専用ブラウザが残った場合はそのウィンドウを閉じ、UIを再起動する。ブラウザのプロファイルロックを無条件に削除したり、すべてのChromiumを一括終了したりしない。

実機で、本人によるログイン、YouTube Musicの実再生・USB DAC出力、ナビへの移動中の音声継続、停車制限、音源切替、終了後の再起動を確認する。Spotifyは加えてARM64ブラウザのDRM・コーデックを確認する。現時点でこれらの実サービス試験は未実施。

## 4. 設定と警告

設定画面の「適用・保存」で以下を検証・保存する。保存失敗時は確定済み設定を維持する。「初期値」は編集欄を変更するだけで、適用までは保存しない。

| 項目 | 初期値 | 許容範囲・反映先 |
| --- | --- | --- |
| 明暗テーマ | ダーク | QMLの背景・文字・操作部品。ディスプレイ輝度ではない |
| アニメーション | ON | 共通画面切替 |
| 起動画面 | ホーム | ホーム・ナビ・カメラ・音楽・車両情報・設定。次回UI起動から使用 |
| 水温警告 | 105°C | 80～130°C。期限内のOBD2水温が設定以上なら警告 |
| 低電圧警告 | 11.8V | 10.0～15.0V、画面操作は0.1V刻み。期限内のECU電圧が設定以下なら警告 |

警告値は動作確認用の初期値で、実車の整備・保護基準を保証しない。実車仕様に合わせて確認する。

設定は`preferences.json`、バックアップは同じ場所の`preferences.backup.json`。一時ファイルを同期して置き換え、破損時には初期値と警告で起動する。保存済みの利用者設定がなければ、起動画面には従来の`ui.json`指定を使う。復元には確認ダイアログを表示する。カメラ・Drive設定、認証情報はこのバックアップの対象外。

同じ`preferences_path`を使用するUIの二重起動はOSファイルロックで拒否する。ロックファイルが残っていても、プロセス終了でロックは解除されるため手動削除は不要。設定保存には別の短時間ロックと読込時点の内容比較を使用する。他処理が変更していたら上書きせず、「再読込」の確認後に編集し直す。外部エディタ等、同じロックに参加しない書込との厳密な排他は保証しない。設定と履歴は同一PCのローカルファイルシステムに置く。

警告は上部バーと一覧に表示する。「確認」は既読にするだけで異常解除ではない。測定不能になった場合も正常回復とみなさない。回復後の再発は未確認の別履歴になる。履歴は最大100件、`preferences.warnings.json`（設定ファイル名が異なる場合はその拡張子を除いた名前+`.warnings.json`）に保存する。変更時だけ非同期保存し、正常終了時にも保存する。保存失敗時は表示で通知し、30秒後に再試行する。突然の電源断で未保存の直近履歴を失う可能性はある。

再起動前に発生中だった警告は「前回の警告・現在は未確認」と表示し、現在の警告バナーには使わない。新しい異常通知が届いたら新規の未確認警告を作る。履歴の破損・未対応形式・1MB超過を検出した場合は既存ファイルを上書きせず、その起動中はメモリだけに履歴を保持する。

## 5. 録画と再生

設定画面で録画サービスから現在値を取得する。録画ON/OFFと60・120・180秒の分割時間だけを変更できる。設定は共通SQLite台帳の`settings`テーブル、`camera_ui_settings`キーへ保存し、次のサービス起動時も使用する。この2項目は保存済み台帳値が`camera.json`より優先される。他の機器・保存先設定はJSONで管理する。

OFF要求は表示用映像を止めず、録画中のファイルを確定する。適用応答は設定の保存・交換完了であり、すべての動画の確定完了ではない。停止結果は録画状態表示で確認する。

録画一覧は日付と方向で検索する。日付は運用OSのタイムゾーンで台帳の確定時刻を検索する。1ページ50件。クラウドへ送信済みでもローカルに残る動画は再生可能だが、削除中・削除済みの動画は再生しない。

再生開始時に共通ファイルロックを取り、ファイルの同一性を検証して一時フォルダへコピーする。UIはコピーをQtMultimediaで再生するため、Driveが元動画を削除しても再生を継続できる。コピーは最大512MiB、コピー後に64MiB以上の空き容量が必要。コピー取得失敗時は元動画も台帳も変更しない。次の再生・UI正常終了でコピーを削除する。異常終了時にはOSの一時フォルダにコピーが残る可能性がある。

Windowsでは前のデコーダがファイルを保持している間、次のコピーを拒否する場合がある。その場合は停止後に再試行する。

### 停車確認による操作制限

設定の変更・復元、録画設定適用、送信の一時停止・再開、プレイリスト編集、録画動画再生は、原則として有効なOBD2車速通知で停車を確認した場合に受け付ける。`validity=VALID`、`unit=m/s`または`km/h`、有限の数値`value=0`、正の有限数`valid_for_ms`が必要。表示上の四捨五入では判定しない。許可期限は通知の残り期限と5秒の短い方とする。有効な車速が走行中を示す場合は操作を禁止する一方、OBD2未接続・車速未取得・車速値失効など、車速そのものを取得できない場合は警告を表示した代替モードとして操作を許可する。車速0の停車確認期限だけが切れた場合は、車速が有効なら操作を許可しない。設定画面は開けるが、代替モードでは停車確認済みとは表示しない。バックアップ、一覧照会、警告確認等の読取系はControllerで停車条件を要求しない。

録画再生は走行開始・車速値失効で停止し、準備中のコピーが後から完成しても表示しない。QMLのボタンだけでなくPythonの操作窓口でも判定する。ただし受付済みの設定書込やサービスへの要求は取消できない。これはOBD2観測に基づく開発用制限であり、パーキングブレーキ検出やハードウェアの安全インターロックの代替ではない。通知周期・遅延・失効を実車で検証する。

停車判定の時刻はUIと同一OSで動作するOBD2サービスの`acquired_mono`（取得時点の単調時刻・秒）を使用し、`time_quality=monotonic`を必須とする。取得時刻なし・未来の時刻・既に失効した通知は操作許可に使わない。通知の受信が遅れた分だけ有効期限を延ばすこともしない。

OBD2を接続していないWindows・仮想環境では、画面に「OBD2車速を取得できないため、停車確認なしで操作を許可しています」と表示して代替モードで操作を許可する。有効な車速が走行中を示す通知を受けた場合は、代替モードを解除して操作を禁止する。車速0の有効期限だけが切れた場合は、車速値が有効なら代替モードへ切り替えない。運用設定に制限解除のスイッチは設けない。これは開発・試験を継続するためのUI動作であり、実車の安全インターロックの代替にはならない。

## 6. クラウド送信と冷却

送信の一時停止・再開だけを設定画面から操作する。現在の送信単位が終了するまで待つ場合がある。再開しても認証・許可ネットワーク・送信量の制限は解除しない。自動削除の設定も変更しない。

車両情報画面は冷却サービスのCPU温度、冷却ファンの回転数、PWMの割合を表示する。保護動作・通知途絶を警告し、未観測値を正常な0として表示しない。

冷却通知は`schema_version`、`boot_id`、`sequence`を検査し、同一Pi 5の`observed_at_monotonic_ms`から5秒で失効させる。UI内で配送が遅れた通知によって期限を延長しない。旧バージョンの`"1.0"`表記は整数1へ変換してから検査する。

## 7. 試験

UI用Python環境へ`requirements-ui.txt`、動画試験用に`requirements-camera.txt`を導入する。WindowsのPowerShell例:

```powershell
$env:PYTHONPATH = "src/raspberry_pi5;src/raspberry_pi3b"
python -m unittest tests.ui_features.test_features -v
python -m unittest tests.ui_features.test_extensions -v
python -m unittest tests.ui_features.test_official_music -v
python -m unittest discover -s tests -t . -v
```

Linuxでは`PYTHONPATH`の区切りを`:`にする。`-t .`はテスト用の`camera`等と実装パッケージを区別するために必要。

追加試験では、履歴の復元と破損保持、設定競合、二重UI起動、車速未取得時の警告付き許可、微速・有効な走行車速・車速値失効・停車確認期限切れ時の禁止、コピー準備中の走行開始、601件の曲一覧、プレイリスト外部変更・書込拒否、USB DAC照会失敗を確認する。800×480と1280×720のQML画面・編集ダイアログも描画する。

実車投入前に、音楽実再生、実Mopidyバックエンドへのプレイリスト書込、DAC抜差し、録画とDrive削除の同時実行、ファン実通知、Linuxソケット権限、Sway重なり順、車速の更新遅延と操作禁止を確認する。自動試験は実車の停車判定・音声出力試験の代わりにはならない。
