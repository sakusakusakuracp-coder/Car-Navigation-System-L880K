| 項目 | 内容 |
| --- | --- |
| 対応設計 | [06 カメラ表示・録画](詳細設計/06_カメラ表示録画.md) |
| 実行環境 | Raspberry Pi 5、64bit Raspberry Pi OS、Python 3.11以上 |
| ソース | `src/raspberry_pi5/camera_service.py`、`camera/` |
| 更新日 | 2026-09-26 |
| 検証範囲 | 実JPEGからのMKV生成・再生、TCP経由受信、確定回復、容量予約、QML画像表示。CSI実機・4方向同時性能・Linux Unixソケットの実機接続は未確認 |

## 1. 入力と保存形式

| 方向 | 入力 | 現在の実装 |
| --- | --- | --- |
| 左・右 | Pi 5のMIPI CSI | Picamera2で指定番号のカメラを開き、JPEGを取得 |
| 前 | Pi 3B サブコントローラ2 | 既存のJSON Lines/JPEGをゲートウェイ経由で受信 |
| 後 | Pi 3B サブコントローラ1 | 同上。バックギア信号とは別の映像データとして処理 |

JPEGを再圧縮せず、PyAVで方向別のMKVへ格納する。60秒を標準とし、容量上限・再接続・画像寸法の変化でもファイルを区切る。録画はUIとは別プロセスで動作し、画面をホームへ戻しても続く。

前後の既存ゲートウェイに`GET_FRAMES`を追加したため、Pi 5側のゲートウェイも同じコミットの内容へ更新する。ゲートウェイは前後それぞれ16画像まで保持し、上限を超えた場合は古い画像を捨てて欠落数を報告する。録画サービスだけがこのキューを取得する。UIはゲートウェイへ直接接続しない。

## 2. 依存ライブラリ

リポジトリを`~/codex-latest`へ配置した例。

```bash
cd ~/codex-latest
sudo apt update
sudo apt install python3-venv python3-picamera2
python3 -m venv --system-site-packages .venv-camera
.venv-camera/bin/python -m pip install -r src/raspberry_pi5/requirements-camera.txt
.venv-camera/bin/python -c "import av; from picamera2 import Picamera2; print(Picamera2.global_camera_info())"
```

Picamera2はRaspberry Pi OSのパッケージを使用する。仮想環境に`--system-site-packages`を指定し、OS側のlibcamera/Picamera2を参照できるようにする。UIの既存仮想環境を使う場合も、Picamera2のimportが成功することを確認する。Debian VMでCSI入力を実行できるとは扱わない。

## 3. 設定

```bash
install -d -m 700 ~/.config/l880k-car-navigation
install -d -m 700 ~/.local/state/l880k
install -d -m 700 ~/l880k-recordings
cp -n src/raspberry_pi5/config/camera.example.json ~/.config/l880k-car-navigation/camera.json
nano ~/.config/l880k-car-navigation/camera.json
```

| 設定 | 初期値・注意 |
| --- | --- |
| `recording_root` | `~/l880k-recordings`。実際にSSDへ保存されるディレクトリへ変更し、起動前にマウントを確認する |
| `catalog_path` | `~/.local/state/l880k/drive-upload.sqlite3`。07と同じDBと録画先を指定する |
| `local_cameras` | `left: 0`、`right: 1`は例。接続カメラ一覧と実画像を確認して左右を確定する。使わない場合は`{}` |
| `remote_cameras` | `front`、`rear`。使わない場合は`[]` |
| `gateway_host` / `gateway_port` | Pi 5上のゲートウェイ、`127.0.0.1:45050` |
| `width` / `height` / `fps` | 左右CSIの取得設定。1280×720、10fps。前後の画質はサブコン側設定に従う |
| `max_frame_bytes` | 1画像400,000バイト。既存ゲートウェイの上限も同じ。大きい画像は画質を下げる |
| `queue_frames` | 録画待ち16画像/方向。上限時は欠落を記録する |
| `frame_valid_for_ms` | 受信後1,500msで表示を失効。撮影から受信までの遅延保証ではない |
| `segment_duration_s` | 60秒、最大180秒 |
| `segment_max_bytes` | 256MiB。全方向で容量予約を共有し、ファイル終端用余裕を含めて分割する |
| `low_space_bytes` / `resume_space_bytes` | 残り予約も差し引き、512MiB未満で新規録画を停止。1GiB以上の余裕で再開判定 |
| `recording_enabled` | `true`。`false`なら表示だけで、録画キューへ入れない |
| `shutdown_timeout_s` | 終了時の待機上限20秒。超過や録画確定失敗は異常終了として報告する |

UI設定画面から録画ON/OFFと分割時間60・120・180秒を変更できる。台帳に保存されたこの2項目がある場合、再起動時もJSONファイルより優先する。OFF後は書込中動画の確定を待って停止する。録画検索・再生と設定保存の詳細は[付録9](付録9_UI追加機能導入手順.md)を参照。

## 4. 手動起動と終了

最初に設定と依存だけを検査する。このコマンドはカメラを開かない。

```bash
.venv-camera/bin/python src/raspberry_pi5/camera_service.py \
  --config ~/.config/l880k-car-navigation/camera.json --check
```

前後を使う場合は、別ターミナルでゲートウェイを起動する。既にsystemdで起動している場合は二重起動しない。

```bash
.venv-camera/bin/python src/raspberry_pi5/subcontroller_gateway_service.py \
  --host 0.0.0.0 --port 45050
```

サブコントローラ側の送信先をPi 5のLANアドレスと45050番へ設定する。通信相手名とカメラ方向は検査するが、暗号化・相互認証は未実装なので、車載機器用の管理されたネットワークで接続する。

```bash
.venv-camera/bin/python src/raspberry_pi5/camera_service.py \
  --config ~/.config/l880k-car-navigation/camera.json
```

UIは従来の起動方法で起動する。同じログイン利用者の`$XDG_RUNTIME_DIR/l880k-camera.sock`へ自動接続する。別のソケットを使う場合はサービスの`--socket`とUIの`L880K_CAMERA_SOCKET`を同じ値にする。

カメラ画面で方向を選ぶと実JPEGを表示する。映像が途絶えた場合は前の静止画像を消す。方向別の接続状態・録画状態と実際の空き容量を表示する。バックギアからの自動切替は別の車体信号連携経路の確認が必要である。

手動起動の録画サービスは`Ctrl+C`で終了する。SIGINT/SIGTERMを受けると新規セグメント開始を止め、開いている動画を確定する。UI終了だけでは録画を停止しない。

## 5. 自動起動

`src/raspberry_pi5/systemd/l880k-camera.service`は配置先`~/l880k-car-navigation`、Python環境`.venv`を例示している。実際の配置先と使用した仮想環境へ`WorkingDirectory`、`ExecStart`、`PYTHONPATH`を書き換えてから登録する。

```bash
install -d ~/.config/systemd/user
cp src/raspberry_pi5/systemd/l880k-camera.service ~/.config/systemd/user/
nano ~/.config/systemd/user/l880k-camera.service
systemctl --user daemon-reload
systemctl --user enable --now l880k-camera.service
journalctl --user -u l880k-camera.service -f
```

前後を使う場合は既存の`l880k-subcontroller-gateway.service`も正しい配置先で登録する。停止は次のコマンドで行う。

```bash
systemctl --user stop l880k-camera.service
```

カメラ・録画先・UIへの権限は同じ運用ユーザーで設定する。userサービスはユーザーセッションの運用に従うため、Piの起動時にどの利用者で開始するかも確認する。

## 6. Google Driveとの接続

1. カメラとDrive設定の`recording_root`、`catalog_path`を一致させる。
2. [付録7](付録7_GoogleDriveアップロード導入手順.md)に従ってDrive認証・通信許可を設定する。
3. カメラが生成した確定MKVが`recordings`テーブルへREADY登録されることを確認する。
4. Drive側の定期照会でアップロードを開始する。通常は手動`register`が不要になる。

動画の書込中は`capture_segments`だけに記録する。終端処理・全フレーム復号検査・サイズ照合・fsync・改名・ディレクトリ同期の後でREADY登録する。録画途中の`.part`をアップロードしない。確定証拠のある未登録ファイルは再起動時に再検査して登録する。証拠のない末尾はINCOMPLETEとして保持する。

録画サービス自身は動画を削除しない。Driveの検証後削除は既存の07の設定に従う。実Driveへの連続アップロード・削除との同時負荷試験は別途必要。

## 7. 試験と残る懸念

```bash
export PYTHONPATH="$PWD/src/raspberry_pi5"
.venv-camera/bin/python -m unittest discover -s tests/camera -p test_camera.py -v
```

QML試験にはPySide6が必要。GUIを画面に出さずに800×480と1280×720で描画する。

```bash
.venv-camera/bin/python -m pip install -r src/raspberry_pi5/requirements-ui.txt
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software \
  .venv-camera/bin/python -m unittest discover -s tests/camera -v
```

自動試験で確認する項目は、分割後の実再生、記録時間の間隔、入力世代変更、破損時の引渡し禁止、確定登録失敗からの回復、容量予約の競合、旧世代・期限切れ画像の排除、キュー上限、TCP受信から録画までの接続、UI画像表示と方向変更・期限切れである。

実機で残る懸念は次のとおり。

- Pi 5で4方向のJPEG処理・録画・再生検査を並行したときのCPU負荷、熱、欠落、通信量、SSD保存量。特に60秒ごとの全フレーム再生検査中にキューが満杯にならないかを測定する。
- 前後の時計同期がないため、受信時刻で再生間隔を作る。撮影時刻の同期が必要なサラウンドビューには、そのまま使用できない。
- 現行サブコンのGPIO監視と画像取得が同じループにある。撮影遅延が車体信号監視へ及ぼす影響を実測する。
- 入力APIやSSDがOS内で応答しなくなった場合、Pythonスレッドを強制的に中断できない。サービスの待機は20秒、systemdの停止猶予は30秒とし、未確定末尾の完全保存を保証しない。
- 実カメラの左右番号、Picamera2の動作、Linuxのソケット権限、起動時のSSDマウント、Driveへの実送信・検証後削除は実機確認が必要。
