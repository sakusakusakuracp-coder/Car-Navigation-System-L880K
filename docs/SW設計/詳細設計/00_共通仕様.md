# 詳細設計 共通仕様

[詳細設計一覧](README.md)

## 1. 適用と優先順位

未実装部分の内部契約を揃えるための設計案。第三者製品のAPI仕様ではない。
上位設計の機能要求、実機の電気仕様、採用ライブラリの制約を確認して確定する。
既存2プログラムは実コードの定数・動作を各設計書に明記し、本仕様への準拠を実装済みとは扱わない。
ハードウェア参照元は[ハードウェア設計書](../../HW設計/ハードウェア設計書.md)。

## 3. 状態通知の共通データ

名称は論理フィールド。JSON等の実際の符号化は実装着手時に固定する。

| フィールド | 型・意味 |
| --- | --- |
| schema_version | 整数。未対応バージョンは拒否し互換性エラーを通知 |
| source / boot_id | 送信サービスID / 起動ごとに変わるID |
| sequence | 同一起動中に単調増加する整数。重複・逆順を検出 |
| observed_at_utc | 測定時刻。UTC未同期時はnullとし、正確な時刻を捏造しない |
| age_ms_at_send | 測定から送信までの経過時間。送信元の単調時計で計算 |
| valid_for_ms | 測定からの有効期間。再送時に延長しない |
| validity | VALID / DEGRADED / STALE / UNKNOWN / FAULT |
| value / reason | 値と状態理由。取得失敗を0に変換しない |

受信側は自ホストの単調時計で最終受信と経過時間を管理する。
異なるホストの単調時計同士を引き算しない。送信前の経過時間と受信後経過時間に通信遅延の上限を含めて期限を判定する。
再接続時は古いキューを捨てて最新サンプルを要求する。車速・リバース等の安全判断は、許容遅延を検証できない場合UNKNOWNにする。
タイムアウトや信頼度の閾値は各データに別々に設定し、未設定の安全機能は有効化しない。

### 3.1 状態名の使い分け

「接続済み」「準備完了」「利用可能」は同じ意味として扱わず、次の状態を分けて通知する。

| 状態名 | 対象 | 意味 |
| --- | --- | --- |
| `transport_status` | 通信経路 | ソケットやTCP接続が確立し、JSONを送受信できる状態。相手のプロセス稼働やデータの有効性は保証しない |
| `service_status` / `service_health` | サービス・プロセス | 対象サービスが起動中・停止中・異常などの状態。通信経路がつながっていてもサービス異常の場合がある |
| `validity` / `data_validity` | 測定値・通知データ | 値が期限内で利用できるかを示す状態。`VALID`、`DEGRADED`、`STALE`、`UNKNOWN`、`FAULT`を使用する |
| `provider_status` | Android位置情報 | Android側の位置プロバイダ登録状態。`REGISTERED`はLocation APIへの登録成功を示すだけで、OsmAndの表示反映を保証しない |
| `display_status` | Waydroid・OsmAnd画面 | アプリの起動、表示面への配置、前面表示の確認状態。アプリ起動済みでも表示未確認の場合がある |

UIでは「通信接続済み」「サービス稼働中」「データ有効」「Android登録済み」「画面表示確認済み」を別々に表示・判定する。状態理由と最終観測時刻も併せて保持し、上位の状態を下位の確認だけで推測しない。

## 4. コマンドと応答

| 項目 | 規則 |
| --- | --- |
| コマンド | command_id、発行元、操作名、引数、有効期限を持つ |
| 応答 | ACCEPTED / RUNNING / SUCCEEDED / REJECTED / FAILEDと理由 |
| 重複 | 同じcommand_idを再実行せず、既知の結果を返す |
| 期限切れ | 受理しない。ドアロック等は再起動後も再生しない |
| 通信断 | 実行結果が不明ならUNKNOWN。成功扱いしない |
| 任意操作の禁止 | 未知の操作名、任意シェル文字列、任意ファイルパスを受け付けない |

データ配信は最新値優先の有界キュー、録画確定・アップロード作業は永続キューにする。
共有ファイルの書き換えを無制限にポーリングする方式は採用しない。

## 5. 単位と位置情報

内部の車速はm/s、距離はm、温度はdegC、回転数はrpm、時刻間隔はmsまたはsを明記する。
UIだけでkm/h等へ変換する。座標はWGS84緯度経度deg、方位は真北0度・時計回りを外部契約とする。
補正内部のENU / radとの変換は03 現在地補正が所有する。IMU軸・センサー取付方向・磁北から真北の補正は校正値として扱う。
位置には水平精度m、推定方法、測定時刻、有効性を付ける。GPS受信断でも同じ位置を「新規測位」として送信しない。

## 6. 録画とアップロードの所有権

| 状態 | 主担当 | 許される処理 |
| --- | --- | --- |
| WRITING | 06 カメラ表示・録画 | 追記のみ。他サービスはアップロード・削除しない |
| READY | 06 カメラ表示・録画から07 Google Driveアップロード・削除へ引き渡し | クローズ・確定後に不変とする |
| UPLOADING | 07 Google Driveアップロード・削除 | クラウド送信。ローカルは保持 |
| RETRY_WAIT / BLOCKED | 07 Google Driveアップロード・削除 | 通信・認証等の復旧待ち。ローカルは保持 |
| VERIFIED | 07 Google Driveアップロード・削除 | リモートID・サイズ・チェックサム等を検証し永続記録済み |
| DELETING / DELETED | 07 Google Driveアップロード・削除 | 録画ルート内の一致する確定ファイルだけ削除 |
| INCOMPLETE | 06 カメラ表示・録画 | 異常終了で未確定。回復可否を調べ、勝手に正常録画としない |

永続管理はSQLiteを候補とし、file_id、camera_id、boot/session ID、相対パス、サイズ、チェックサム、開始終了UTC、有効な時刻の有無、状態、リモートID、試行回数を保持する。
ファイル操作とDB更新は単一トランザクションにはできないため、再起動時に照合して回復する。
チェックサム計算方式はクラウドが提供する検証値との一致を確認して選ぶ。ETagを無条件にMD5とは扱わない。

## 7. 権限・ログ・設定

- 各デーモンは必要最小限のGPIO・カメラ・保存先権限で動かす。UIは通常ユーザーで起動する。
- Android連携・サブコン通信は車載内の許可された相手に限定する。インターネットへ制御APIを公開しない。
- Driveの認証情報、Wi-Fi資格情報、位置履歴をソースや公開Gitへ含めない。秘密値をログへ出さない。
- 設定は起動時に型・範囲・参照先を検証する。設定例と実値を分ける。秘密設定は別管理する。
- ログは時刻、サービス、イベント、状態、理由、相関IDを持つ。容量・保持期間を制限する。
- Linuxサービスは停止要求を受けて新規作業を止め、期限内に保存・解放する。依存順序と停止期限は実機で確定する。

## 8. 統合試験の前提

各文書の単体試験の後、車体から切り離した信号模擬、実機ベンチ、停車中の確認の順に進める。
走行中に画面操作やデバッグを行わない。カメラ・推定位置・車両値は運転者の直接確認の代わりにしない。
本詳細設計の作成時点では試験を実施していない。

## 9. 共通用語

| 用語 | 日本語での意味 |
| --- | --- |
| JSON Lines | 1行に1つのJSONオブジェクトを記述して送受信する形式。改行をメッセージの区切りにする |
| IPC | 同じコンピュータ上で動くプログラム同士の通信。今回の主な方式はUnixドメインソケットである |
| dry-run | 実際のGPIO、カメラ、車体回路、外部送信を行わず、入力・制御・状態遷移だけを確認する試験モード |
| 台帳（カタログ） | 録画ファイルの識別子、保存場所、サイズ、状態、送信結果を記録する管理データ |
| 処理所有者ID | 1つの録画ファイルを現在処理しているサービスを識別するID。二重送信・二重削除を防ぐために使用する |
| valid_for_ms | 測定値を受信後も有効とみなせる期間をミリ秒で示す値。再送しても期間は延長しない |
| provider | Androidが位置情報を受け取る登録先。`REGISTERED`は登録成功を示すが、OsmAndへの画面反映は保証しない |
| RECEIVED | 通信相手からの要求を受信し、形式・識別子の検査を通過した状態 |
| REGISTERED | Androidの位置情報APIへの登録処理が成功した状態。OsmAndの表示成功とは別である |
| INVALIDATED | それまで登録していた位置を無効化する処理が成功した状態 |
| PhotoMOS | 入力側のLEDと出力側の半導体スイッチを光で絶縁した部品。J2電源ボタンの接点短絡などに使用する |
| Hi-Z | 高インピーダンス状態。端子を電気的にほぼ切り離し、外部回路へ電圧を積極的に出力しない状態 |
| open_drain_low | 通常はHi-Zにし、動作時だけLOWへ引き下げるGPIO駆動方式。接点短絡や共有信号線に使用する |
| Foreground Service | Androidで利用者へ動作を通知しながら継続処理するサービス。無期限に動作できることを意味しない |
| 外部サーフェス | Waylandコンポジタへ外部アプリが提供する表示面。現行実装では完全埋込みではなく、Swayの外部ウィンドウ配置を使用する |
| PTS | 映像フレームの表示時刻。Presentation Timestampの略 |
| RTP | 音声・映像をネットワークで運ぶための通信方式。Real-time Transport Protocolの略 |
| GOP | 映像の一つの圧縮単位。Group of Picturesの略で、先頭の基準フレームと後続フレームのまとまり |
| backpressure | 受信側が処理しきれないとき、送信側へ速度低下や停止を要求する仕組み |
| T.B.D | To Be Determinedの略。採用方式、数値、実機条件などが未確定であることを示す |
