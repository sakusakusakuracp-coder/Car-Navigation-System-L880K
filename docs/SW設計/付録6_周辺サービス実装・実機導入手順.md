# 付録6 周辺サービス実装・実機導入手順

冷却ファン制御、サブコントローラ1/2、ドアロック制御の内部実装を確認する手順をまとめる。
実装済みとは実機接続済みという意味ではない。車体信号、GPIO極性、カメラ、保護・駆動回路の受入が完了するまで、実車機能を有効にしない。

## 1. 開発環境でのdry-run（実機入出力を行わない試験）

リポジトリのルートで実行する。サブコントローラのdry-runは、実際のGPIO、カメラ、車体回路を操作せずに制御則と状態遷移を確認するモードであり、Pi 5のゲートウェイがなくても起動できる。接続失敗は警告して処理を継続する。

```sh
export PYTHONPATH="$PWD/src/raspberry_pi5:$PWD/src/raspberry_pi3b"

python src/raspberry_pi5/fan_control_service.py \
  --config src/raspberry_pi5/config/fan_control.example.json \
  --dry-run --once

python src/raspberry_pi3b/sub_controller1_service.py \
  --config src/raspberry_pi3b/config/subcontroller1.example.json \
  --dry-run --once

python src/raspberry_pi3b/sub_controller2_service.py \
  --config src/raspberry_pi3b/config/subcontroller2.example.json \
  --dry-run --once

python src/raspberry_pi5/door_lock_service.py \
  --config src/raspberry_pi5/config/door_lock.example.json \
  --dry-run --once
```

## 2. Raspberry Pi 5への導入

1. `src/raspberry_pi5/config/`の設定例を`~/.config/l880k-car-navigation/`へコピーする。
2. 冷却ファンは4ピンPWM標準の25kHz（許容21kHz-28kHz）を使用する。PWM GPIO、Linuxの`pwmchip`/チャンネル、TACH GPIO、ファン仕様、温度閾値を実測してから`enabled=true`にする。`lgpio.tx_pwm`を25kHz出力に使わない。
3. ドアロックは回路の極性・パルス幅・車速条件・外部解除を受入した後だけ、GPIOと出力レベルを設定して`enabled=true`にする。
4. サブコン通信はPi 5のゲートウェイをTCP/45050で待ち受ける。ネットワーク分離と相手確認は実機導入時に追加する。
5. 実行ユーザーにGPIOデバイス、カメラ、結果記録先への必要最小限の権限だけを与える。

```sh
mkdir -p ~/.config/l880k-car-navigation
cp src/raspberry_pi5/config/fan_control.example.json ~/.config/l880k-car-navigation/fan_control.json
cp src/raspberry_pi5/config/door_lock.example.json ~/.config/l880k-car-navigation/door_lock.json
```

systemdユーザーサービスとして登録する場合は、`src/raspberry_pi5/systemd/`のユニットを`~/.config/systemd/user/`へコピーし、`ExecStart`内のリポジトリパスを実際の配置先へ変更してから次を実行する。

```sh
systemctl --user daemon-reload
systemctl --user enable --now l880k-fan-control.service
systemctl --user status l880k-fan-control.service
```

ドアロックは受入完了まで自動起動しない。ゲートウェイはPi 5側の常駐サービスとして登録し、ドアロックとは分けて管理する。

## 3. Raspberry Pi 3Bへの導入

各Pi 3Bへリポジトリの`src/raspberry_pi3b/`を配置し、設定例をコピーする。設定例は`configuration_state=candidate`相当の扱いで、実機起動時は拒否される。GPIO番号、入力極性、ネットワーク相手を実測確認した後に`confirmed`へ変更する。

```sh
mkdir -p ~/.config/l880k-car-navigation
cp src/raspberry_pi3b/config/subcontroller1.example.json ~/.config/l880k-car-navigation/subcontroller1.json
cp src/raspberry_pi3b/config/subcontroller2.example.json ~/.config/l880k-car-navigation/subcontroller2.json
```

実機では`lgpio`と、CSIカメラを使用する場合のRaspberry Pi OS提供`picamera2`、JPEG変換用Pillowを導入する。車体12V信号は必ず保護回路を通し、GPIOへ直接接続しない。

## 4. 状態通知と安全上の注意

- サブコン1/2はEthernet TCP/45050のJSON Linesで状態と映像メタデータを送る。Pi 5側は`boot_id`と`sequence`で古い通知を破棄する。
- 冷却ファンは1台へPWMを出し、同じファンのTACHを取得する。回転数が取得できない場合は正常と推定しない。
- ファンPWMはLinux PWM sysfsで出力し、PWM周波数をオシロスコープまたは周波数計で25kHz前後と確認する。設定値だけで合格にしない。
- ドアロックはLOCK/UNLOCKの同時出力を禁止し、車速が有効かつ停車条件を満たす場合だけ短時間パルスを出す。
- 出力開始前の記録に失敗した場合は出力しない。出力後に解除結果が不明な場合は自動再実行せず、`UNKNOWN`として扱う。
- `--dry-run`は制御則の確認用であり、実際のGPIO、カメラ、車体回路の正常性を証明しない。
