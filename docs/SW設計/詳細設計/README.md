## 共通の章構成

一般的なソフトウェア詳細設計の構成を採用する。特定の規格への適合を表明するものではない。

| 章 | 内容 |
| --- | --- |
| 1 | 目的・適用範囲 |
| 2 | 要求仕様・責務 |
| 3 | 内部構成 |
| 4 | インターフェース設計 |
| 5 | データ・設定設計 |
| 6 | 処理・状態遷移 |
| 7 | 異常処理 |
| 8 | 起動・終了・運用設計 |
| 9 | 試験・受入条件 |
| 10 | 未確定事項・実装課題 |

各文書の目次は固定アンカーで移動する。[共通仕様](00_共通仕様.md)には、通信データ、時刻、状態、録画ファイルの所有権などの横断ルールを記載する。

Linuxカーネル、ドライバ、gpsd、Waydroid、OsmAnd、Mopidy、LIVIは自作ソフトとして数えない。

## 設計・実装の扱い

- 現時点で内部実装済みの対象コードは、Pi 5状態通知、Pico電源管理、03現在地補正、04 Linux位置情報連携、05 Android位置情報連携、07 Google Driveアップロード、10冷却ファン制御、15/16サブコントローラ、17ドアロック制御である。実機検証前のコードは運用可能とは扱わない。
- オーディオ連携のソース分割は本詳細設計で提案する。ドアロック制御、冷却ファン、サブコン1/2は詳細設計に対応する内部実装を追加済みである。
- 未実装ソフトの関数名・データ名は内部契約の設計案であり、既製ソフトが同名APIを提供するという意味ではない。
- 数値未確定の安全条件は機能を有効にする前に決める。未知の車速を停止中として扱わない。
- 試験表は今後実施する受入試験であり、合格実績ではない。
- Pico GP14はJ2_CONTROL_MODEで方式を選択する。既定active_highは通常LOW・動作時HIGH。HWの吸込み配線図にはopen_drain_low（通常Hi-Z・動作時LOW）を選ぶ。GPIO26 LOWだけではOS停止を確認できず、停止後の自動再起動は保留する。
